# 分类与处置量表

## 判定单位

最小单位是一个能独立影响模型决策的规则块，而不是自然段、文件或整个 Skill。

一个规则块如果同时包含通用步骤与业务标准，优先拆分。拆分会破坏原意时标为 `mixed`。

## 先分仓库角色

`artifact_role` 与 `asset_type` 正交：

- `instruction`：入口与运行指令。
- `reference`：按需或默认加载的知识材料。
- `source`：确定性脚本或程序源码。
- `test`：验证行为的测试。
- `asset`：交付时复制或使用的素材。
- `metadata`：界面、包或版本元数据。
- `historical`：学习记录、决策记录或归档说明。
- `generated`：可重新生成的输出。
- `binary`：构建产物。
- `secret`：凭证、密钥与敏感配置。

`secret`、`binary`、`generated` 必须使用 `asset_type=not_applicable`。它们可以有仓库治理建议，但不能拿来计算通用、临时或独家规则比例。

## 六个观察维度

每项取 0、1、2。分数用于暴露依据，不直接相加得出分类。

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 模型替代度 | 无 Skill 明显不会 | 可能部分完成 | 已有对照证明能稳定完成 |
| 业务独特性 | 跨行业通用 | 含场景约束 | 含私有事实或独家判断 |
| 失败证据 | 没有 | 有原因说明 | 有真实反例、批注或事故记录 |
| 验收价值 | 没有验收标准 | 有模糊标准 | 有可执行测试或明确通过条件 |
| 环境时效性 | 长期稳定 | 随工具变化 | 强绑定临时目录、接口或任务 |
| 维护收益 | 高频且关键 | 尚不明确 | 低频且维护成本明显偏高 |

模型替代度在没有对照测试时最高只能记 1，不得凭审计模型的自我感觉记 2。

## 分类顺序

按以下顺序判断，前项成立就停止外推：

1. 涉及安全、权限、隐私、合规、事实边界或不可逆操作：`proprietary` 或 `mixed`，默认 `keep`、`human_review`。
2. 业务独特性为 2，或验收价值为 2：通常为 `proprietary`。
3. 强绑定一次性任务，复用率低：通常为 `temporary`。
4. 模型替代度有 E2/E3 证据且业务独特性低：通常为 `generic`。
5. 无法区分：`unknown`。

## 分类信号

### generic

常见信号：总结、润色、拆任务、扮演角色、列步骤、生成候选、普通自检。

反证：虽然动作通用，但规则包含独家验收标准、真实失败案例或强制安全边界。

### temporary

常见信号：单批文件、一次迁移、短期 API、特定临时目录、活动期流程。

反证：脚手架已经稳定复用，或承载长期环境契约。

### proprietary

常见信号：真实批注、失败模式、业务词典、个人审美、组织约束、验收测试、权限边界、回滚条件。

反证：只有“要真实”“更有价值”等无法执行的空泛要求。

### mixed

常见信号：一个步骤里既有模型通用动作，又嵌入不可拆开的业务限制。

优先建议 `compress`，只压缩通用说明，保留独特约束。

## 生命周期判定

- `active`：当前真实任务仍依赖。
- `possibly_redundant`：存在冗余迹象，但尚无足够对照证据。
- `model_dependent`：不同模型的需要程度可能不同，或只验证了单一模型。
- `task_dependent`：价值只在部分任务中成立。
- `needs_test`：没有独立验收，无法验证收益。
- `historical`：主要用于解释过去决策，不应默认加载，但可能仍有追溯价值。

## 证据到建议的上限

| 证据 | 允许的最激进建议 |
|---|---|
| E0 | `human_review` |
| E1 | `compress` / `externalize` / `needs_comparison` |
| E2 | `temporary` / `compress`，仅限已测模型与任务 |
| E3 | `archive_candidate`，仍需人工确认 |

出现以下任一条件，不得建议 `archive_candidate`：

- 仍有调用方未检查。
- 包含安全、权限、隐私、合规或不可逆操作规则。
- 包含没有迁移位置的业务事实、失败记录或验收测试。
- 模型版本未知。
- 没有独立验收标准。

## 置信度

- `low`：模型未知、E0/E1、样本不足或来源不完整。
- `medium`：E2 且结论只覆盖一个模型或有限任务。
- `high`：E3，样本覆盖真实任务，验收标准独立且结果一致。

高置信度仍不等于删除授权。

## 两套证据不得混用

`replacement_evidence` 评估模型替代，只能由 Skill 文本判断或有/无 Skill 对照升级。

`behavior_validation` 评估现有实现：

- `untested`：未执行验证。
- `passed`：测试或确定性检查已通过，必须给出证据。
- `failed`：测试已失败，必须记录失败证据。
- `not_applicable`：该项没有可执行行为。

`passed`/`failed` 必须记录实际检查数。退出码为 0 但收集 0 个测试，只能记为 `untested`，并继续寻找仓库声明的真实测试入口。

代码测试通过不能证明模型不需要 Skill；模型生成结果看起来不错，也不能证明权限、回执或回滚实现正确。

## 依赖状态

- `entrypoint`：Skill 入口。
- `direct`：入口直接引用。
- `transitive`：由直接或其他传递依赖引用。
- `unreferenced`：仓库内未发现引用。
- `external_unknown`：可能由仓库外调用，尚未核实。

只有完成外部调用方检查，E3 资产才允许成为 `archive_candidate`。
